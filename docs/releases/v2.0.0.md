# Lecture Caption v2.0.0

A single workspace replaces the three-window layout. Notes appear on the left and bilingual caption history on the right. The newest segment is highlighted and scrolls smoothly; reading older text pauses follow until “回到最新”.

A single compact top toolbar contains logo, input source, recognition/translation backends, English/Chinese/bilingual display, Start/Pause, Stop and a small settings icon. The level meter and locally counted API usage are at the bottom. Note hints disappear after the first content; refresh/folder icon buttons remain in the note pane’s top-right corner. Settings open as a dialog. Opacity, backend, caption-language and typography preferences survive restarts.

Apple local mode is optional: on-device English speech recognition is experimental; English-to-Chinese translation uses Translation.framework on macOS 15+ with language assets installed. Prepare translation packs in Settings. Audio never silently falls back to cloud. Recognition and translation update cumulative utterances periodically; latency includes recognition and translation time.

With both Apple backends selected and automatic notes disabled, captions require no API key. Structured Markdown notes still use your Groq key and send recognized text to Groq. Course glossary prompts apply to cloud recognition; Apple recognition currently uses general English dictation.

## Requirements and verification

- Apple Silicon, macOS 14+ for cloud mode; macOS 15+ for Apple translation. Local English speech depends on system support/resources and speech-recognition permission.
- Application and release ZIP are ad-hoc signed, not notarized. Python and runtime libraries are bundled. Keys, personal recordings, notes and config are excluded.
- Regression tests use synthetic audio and mocked providers; real classroom/meeting accuracy is not implied. Apple translation was checked on macOS 26.6 using a synthetic CS sentence. Microphone/end-to-end local recognition requires user verification.

Download `LectureCaption-2.0.0-macOS-arm64.zip`, extract and drag the app into Applications, replacing the old app after closing it. Existing Keychain credentials and app-data notes remain available. SHA256SUMS.txt covers both binary and source ZIPs.

When Groq returns rate-limit headers, the main window also displays the latest server request/token snapshot with model details in a tooltip. This is not a billing balance or a live combined quota for all models. See [Groq rate-limit headers](https://console.groq.com/docs/rate-limits).

On macOS 26+, local recognition uses SpeechAnalyzer/SpeechTranscriber with explicit AssetInventory preparation. Use **准备 Apple 英文语音资源** in app Settings if assets are missing; toggling system Dictation is not sufficient for this engine. Older macOS uses the legacy on-device Speech API. Synthetic CS audio was verified through the native segment/recognition/Apple-translation pipeline without a cloud request; real classroom microphone accuracy still needs user verification.

Coherent captions now use borderless timestamped paragraphs: black source and blue translation on a light surface, with current-paragraph emphasis. Both Apple and Groq periodically re-recognize cumulative utterance audio and retranslate the complete current text, revising the same paragraph until a natural pause (bounded at 24 seconds for continuous speech). Previous translations remain visible while an update is pending. Notes consume completed paragraphs once; pausing preserves the last recognized draft. Repeated cumulative audio consumes more Groq speech quota than independent slices. Time ranges are approximate capture spans, not word alignment.

Live selectors remain enabled during capture. Translation-only switches keep capture and ASR running and retranslate the current paragraph; source/ASR switches save the latest recognized draft, reconnect input and discard stale-generation results. Unrecognized tail audio may be lost during input reconnection and is marked. The level indicator is green while capturing, grey when idle and a red exclamation on device errors. Daily API allowance sits beside locally counted 24h speech requests, without duration/processing-time clutter. Return-to-latest is a 32px viewport overlay: appears when browsing older text and disappears at the bottom without resizing content.

Notes now revise one coherent document, backed by a cumulative transcript.md. Long lectures send the full previous note document, about 18000 characters of recent whole transcript paragraphs, and all unprocessed text; the complete original stays on disk. Enabling notes sends this accumulated context, including earlier locally recorded content in the current lecture, to the configured notes API.

The notes pane, including its empty placeholder, uses a pure white background.
