# Lecture Caption v2.2.0 — local preview only

Not published. First launch offers a concise guide and one-action Apple or Groq setup. Advanced parameters stay at defaults behind Customize. The selected input's permissions and local resources are prepared in sequence; no recording occurs. Groq opens the official keys page in a native WebKit window, with an external-browser option for restricted authentication providers. Users complete registration/login and create/copy the key themselves; one Paste/Finish action validates model availability, saves to Keychain and prepares permissions. Account passwords, web page contents and clipboard changes are not inspected. Clipboard text is read only when the explicit Paste button is pressed with an empty key field. The microphone bridge runs inside the main app process; screen/system audio preparation never starts a stream. OS denial/restart requirements remain visible and are not bypassed.

Notes are edited directly on a white surface, with a title, bold/italic/H1/H2/H3/lists/highlight/strike toolbar and ellipsis menu (source, immediate Summary, folder). The separate editor dialog is removed. Rich editing, Markdown input and source editing share one document; ==highlight== persists, including in PDF. Command+B/I/H, Command+Shift+X and heading/list shortcuts operate in the note editor. Formatting in code remains literal. Existing Markdown is preserved until edited; rich edits normalize standard Markdown formatting. Inline LaTeX is retained as text, not typeset equations.

Edits are backed up after a short debounce and flushed at End/close. Before-edit snapshots are rate limited. AI updates wait during active editing, and stale responses cannot overwrite newer edits. Explicit Summary can use the current edited/imported document or accumulated transcript; automatic second-pass revision remains timed. End offers Markdown/PDF before asking for a destination, remembers the directory and keeps session backups. Note-only import/edit/export works without starting capture; absent keys never create a cloud client.

Validation uses synthetic documents/audio, mocked provider/permission responses, native compilation, temporary installer tests, local PDF rendering and isolated bundle launch. Real account creation and OS permission decisions remain user actions. No personal recordings, keys or notes are used for testing. Public stable release remains v2.0.0.
